# 知识库路径与文件夹

知识库使用稳定 ID 标识笔记，以可读逻辑路径组织文件夹和移动操作。本文描述路径与链接契约；本机存储见[分记录存储](KNOWLEDGE-STORAGE.md)，日常操作见[知识工作台](KNOWLEDGE-WORKBENCH.md)。

## 使用

- 侧栏是文件系统式目录树（唯一的笔记列表）：文件夹 = 笔记路径推导 ∪ 显式目录登记，笔记行以标题命名、尾随相对时间，搜索、集合、收藏与最近访问筛选作用于整棵树。展开/折叠使用原生控件，支持键盘操作；空笔记（无标题无正文）降级为一行静默标题。
- 树支持右键与拖放：笔记行右键（打开、在新标签打开、重命名、移动到…、收藏、删除），目录行右键（新建子目录、重命名目录、移动到…、删除目录），空白处右键只有新建入口；「新建目录」按钮与右键都以行内输入落位，`/` 一次可建多级。拖笔记或目录到目标目录即移动，拖到空白处移回库根，落点高亮确认；所有移动即时落地并给一步撤销。删除目录前若其中还有笔记，先弹确认（笔记平铺到库根并改写引用，子目录名一并移除）。
- 笔记上方显示当前位置。点击「移动笔记」打开文件夹选择器（「根目录」按钮、文件夹树、「新建文件夹名称」输入），选定目标后**即时移动**，并弹出撤销提示「已移动并更新 N 处链接」或「已移动，无需更新链接」；结果区展示受影响笔记的原/新路径与正文差异，可「撤销移动」或「完成」。目录随目标建立，标题、稳定 ID、收藏、标签页和引用身份不变。没有预览→确认向导。
- 文件夹右侧的移动按钮修改整个目录前缀，包含所有子目录及笔记，不限于当前搜索或筛选结果。目标在文件夹选择器中指定；「根目录」清空目标移至库根，不能移入自身或其子目录。
- 移动与必要的引用更新共用重命名的审阅组件，逐篇展示原路径、新路径及正文差异，并在同一次持久化写入中原子提交。移动前编辑器正文按原有规则自动保存；「撤销移动」一并还原路径与引用。
- 搜索、快速切换与双链补全支持路径，补全结果显示路径，插入仍使用稳定 ID。集合是独立分类字段，不会自动变成文件夹。

空目录（显式登记）、拖放整理与目录删除/重命名已随目录树交互落地；目录展开状态的持久化尚未实现。新建笔记仍先分配稳定 ID 路径，可通过移动获得可读路径。

## 数据与兼容

`KnowledgeNote.path` 是可选字段。旧笔记保持原样，没有该字段时逻辑路径为 `<id>.md`；仅打开知识库不会批量迁移或改名。路径采用 NFC 归一化、`/` 分隔、`.md` 后缀；禁止绝对路径、穿越、隐藏目录、Windows 保留名称和不可移植字符。路径比较不区分大小写，稳定 ID 区分大小写。冲突、文件/目录重叠和占用其他笔记的根目录 ID 别名都会被拒绝，不覆盖已有内容。

显式目录登记在 `KnowledgeContent.folders`（库内相对目录路径，同一套段校验，不带 `.md` 后缀）；派生目录仍由笔记路径推导，两者并集构成目录树。空目录只存在于这份登记里；用户建的目录不会因笔记移走而消失，删除目录会移除整棵子树的目录名，其中笔记平铺到库根。

GitHub 与 ZIP 把显式目录写入 `knowledge/folders.json`；带目录时文件清单版本升为 3，旧客户端会拒绝而不是丢弃目录。本地分记录清单升为版本 4，`folders` 内联在 state 与 base/pending 内容中；读取旧数据（缺 `folders`）按空列表处理，依旧不做批量迁移。三方合并中目录名按集合语义取并集，双方都删除才消失，不产生逐条冲突。

首次持久化含路径的数据时：

1. 校验整个新状态。
2. 将变更前的完整状态保存在元数据键 `workspace/knowledge.before-paths.v1`（已有快照不覆盖）。
3. 将状态版本升为 `2`，写入原有键 `workspace/knowledge.v1`，成功后才通知界面。

版本检查也覆盖历史、同步基线、待确认同步内容与冲突快照。备份失败阻止主写入；主写入失败不发布内存成功状态，下一次操作重新读取持久化状态。旧客户端不识别版本 2，会拒绝加载，而不是忽略路径字段继续写入。

此快照仅是**当前浏览器内的迁移恢复点**，不是独立设备备份；没有直接恢复该元数据键的界面。清理网站数据会连同快照一起删除。操作前建议通过现有「导出知识库」保存 ZIP。不要直接将旧快照写回运行中的新版 Store；恢复需先停止写入、导出当前内容，再通过维护工具处理。

GitHub 和 ZIP 的物理结构继续使用 `knowledge/notes/<id>.md`、`citations/<id>.json`；路径保存在 Markdown 元数据中。包含显式路径时，文件清单版本和对应笔记的 `bcr` 标记升级为 2；其他物理文件不重命名。所有设备均需使用新版客户端。

三方合并把路径作为独立字段：一边移动、一边改正文可合并；竞争移动保留为同步冲突。跨笔记的路径碰撞会拒绝整个提交，需调整冲突路径再重试；尚未提供专门的跨 ID 路径冲突解决面板。恢复同 ID 的「保留双方」副本分配 `(2)` 等路径；不同 ID 占用相同路径的恢复仍会拒绝，不猜测覆盖策略。

## 链接语义与保护

解析顺序：稳定 ID → 当前笔记目录的路径 → 库根路径 → 裸标题。显式 `./`、`../` 不回退到库根或标题；不得越过库根。有斜杠的未命中路径也不回退标题。标题同名返回多个候选，不静默选择。旧 ID 别名不会因大小写折叠而抢占标题匹配。

移动计划对比移动前后的解析结果。对于原本唯一解析的笔记链接，若移动使其失效或转向其他笔记，就转换为稳定 ID 引用，保留文字、别名和标题锚点。这既保护入链，也保护移动笔记自身的相对出链，以及被新路径遮蔽的其他链接。仍能正确解析的链接不改写。

支持简单双链、内联 Markdown 链接及引用式文字链接；后者只转换引用位置，保留定义，避免改动共用定义的图片。歧义或未解析链接不猜测目标；本地 `attachment:<id>` 引用不依赖目录，移动时无需改写；外部相对图片、嵌入、块引用不自动维护，移动前需自行检查这些资源。

移动在应用前校验完整笔记版本集合、草稿与同步冲突，路径与引用更新在同一次写入中原子提交；任一校验失败则整体拒绝，不覆盖已有内容。「撤销移动」同样原子还原路径与引用。修改与历史一次保存；历史仍有全库 100 条上限，大批量整理前建议导出备份。Agent 的单篇审批范围不扩大，也没有开放未经审阅的批量移动工具。

## 实现与验证

- `paths.ts`：可移植路径规范、唯一性、相对路径解析与副本命名。
- `changePlan.ts`：纯函数移动/目录移动计划；`store.ts`：计划签发、并发校验、备份与持久化。
- `markdownAnalysis.ts`：统一路径/ID/标题解析；`renameLinks.ts`：稳定引用替换。
- `NoteFileTree`：目录树本体（导航、右键/拖放、行内目录名输入）；`TreeMenu`：树的右键菜单；`NoteMove`：文件夹选择器与即时移动（含撤销）；`NoteChangeReview`：移动与重命名共享的差异审阅。store 的 `moveNotes`/`moveFolder`/`deleteFolder` 是三条入口共用的即时移动与撤销原语。
