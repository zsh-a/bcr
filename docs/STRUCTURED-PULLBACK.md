# 结构化回调策略与隔离研究流程

这套实现把用户的价格行为思路转成可执行、可审计的机械假设：快速推进确定方向，已确认关键位提供参考，回调结构形成后等待整段推进极值被突破。它使用 30 分钟信号和分钟执行，允许跨日持仓。代码实现一致性与策略是否有正期望是两项独立验收；历史证据见 [首轮记录](../research/trend/structured/ANALYSIS.md)，两项语义优化的验证见 [第二轮记录](../research/trend/structured-v2/ANALYSIS.md)。

入口为 `structured-pullback`，当前配置 v10、执行器 `trend-continuation-16`。旧 v9 结构规则、`price-action`、通道、KDJ 和历史配置保留原语义。策略复用已有账户、成交、成本、风控和评价模块，不增加第二套回测引擎。以下先说明首轮严格规则，v10 两个显式语义选项在后文单独定义。

## 可执行的交易定义

| 层次     | 固定研究规则                                                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 趋势能量 | 三根已完成 K 线的方向位移至少为推进起点 ATR14 的 1.5 倍；净位移除以逐根收盘绝对变化之和至少 0.6。ATR 为起点已经可得的 Wilder ATR，冻结为 A0 |
| 均线辅助 | 主方案用同周期 EMA20/60 排列及既有方向判断；`sp-no-ema` 单独取消该过滤。ATR 自身不提供方向                                                  |
| 推进边界 | 确认后最多延伸八根；第一根逆向收盘开始回调，冻结此前整段推进高／低点，首根回调的影线不再改变该边界                                          |
| 回调资格 | 2–24 根，含首根和触发根；含影线回撤深度为整段推进幅度的 20%–50%，过深或超时立即失效                                                         |
| 结构     | 使用回调内左右各两根确认的转折点；主方案至少命中一种结构。形态可以重合，不能把标签数加成机会数                                              |
| 最终入场 | 收盘超过冻结推进极值至少一 tick，下一分钟开盘模拟成交，含滑点与不利取整。第一次突破即消费机会，不满足门槛也不会等待该形态的下一次突破       |
| 初始风险 | 实际成交价 ± 两倍信号 K 的 ATR，按 tick 不利取整；初始 R 固定，以子账户 0.5% 风险预算决定数量，并受 95% 名义敞口上限约束                    |
| 跟踪退出 | 独立 `chandelier` 管理：每根交易 K 收盘，以入场以来极值减／加三倍最新 ATR，和旧止损合并，单调收紧；无盈利启动阈值，无单独保本               |

推进 A0 与入场 ATR 各有用途，不能混为同一个值。ATR 衡量波动幅度，不保证方向延续；这里的 1.5 倍与 0.6 是待检验假设，不是论文证明的最优阈值。[ATR 官方说明](https://www.tradingview.com/support/solutions/43000501823-average-true-range-atr/)

已有止损先处理当分钟价格，新跟踪线在交易 K 收盘后生成，此后才有效。新线到达或越过当前收盘价时锁定退出意图，在下一分钟可执行开盘成交；不会假设能成交在已经越过的止损价。入场前的最高／最低价不进入持仓跟踪极值。`chandelier` 与旧 `atr`、`staged` 模块的语义分别保存。

## 关键位与形态

30 分钟策略的参考周期为 2 小时，始终只接收完整 K 线。关键位身份在推进起点时确定，后面不会倒选一个更漂亮的位置。

- **已确认高低点**：左右各两根确认。选择起点以前已确认的最近相应转折，起点处于其逆侧或相等；最初三根推进或后续延伸阶段收盘越过后取得资格，进入回调时冻结。回调触碰 ±0.25 A0 容差且收回顺侧才算回踩，逆侧收盘超过容差后失效。
- **此前验证过的 EMA20**：在较大周期上先发生触碰（距当时 EMA 不超过 0.25 个该周期 ATR），再由另一根完整 K 收盘沿相应方向离开至少 0.5 个触碰时 ATR；最近 20 根内有两次这样的确认，且第二次确认不晚于推进起点。其验证身份固定，后续均线值只随已完成较大周期 K 更新，回调必须另有真实回踩记录，复测带宽使用 0.25 A0，即 30 分钟推进前 ATR；它与此前验证使用的 2 小时 ATR 分开。
- 主方案关键位门槛为两者满足其一；没有把二者同时满足设成必要条件。关闭关键位门槛的对照仍观察同样的关键位，保持预热和识别过程一致。

| 回调标签   | 因果定义                                                                                           |
| ---------- | -------------------------------------------------------------------------------------------------- |
| 两段回调   | 两个已确认逆势极值之间存在一个已确认顺势反弹极值                                                   |
| 三推楔形   | 三个逐次更深的逆势极值，第三推扩展幅度小于第二推，两个反弹极值沿回调方向下降；做空镜像             |
| 平行通道   | 两对交替极值构成两条逆势轨道；按整个跨度计算，两轨斜率差造成的位移不超过 0.25 A0，宽度至少 0.25 A0 |
| 双底或双顶 | 最近两个逆势极值差不超过 0.25 A0，中间反弹幅度至少 0.5 A0                                          |

转折发生时间和确认时间分别保存。突破当根即使足以确认一个旧转折，也不会把它加入本次突破前的形态证据。双重外包 K 可能同时构成高低点，分钟 OHLC 无法确定内部次序，因此不按任意顺序造出两个转折。[TradingView 关于转折回填与高周期未来信息的说明](https://www.tradingview.com/pine-script-docs/concepts/repainting/)

在这套定义下，其余三个标签都是“两段回调”的细分，`shape:any` 与 `shape:two-legs` 的准入集合相同；保留细分标签用于解释和后续假设设计，不把它们包装成四个独立策略。Brooks 的教学中三推也可能呈近似平行结构；本项目更严格的数值标签只是一个可重复的版本。[Brooks 本人的形态讲解](https://www.brookstradingcourse.com/trading-strategies/5-steps-to-finding-todays-trades/)

信号快照另记录实体吞没、十字星、双十字星、内包／外包、窄幅整理和反转标签。双十字星取突破前两根，实体不超过各自振幅的 10%；窄幅取此前三根总区间不超过 A0。主方案不额外要求这些烛形，另有 `sp-reversal` 比较吞没或强外包确认的作用。最终交易触发始终是整段推进极值突破，不能称为 Brooks 在信号 K 上方一 tick 的原版规则。

分钟 OHLCV 无法还原真实筹码成本分布，本版没有制造“筹码区间”。主观趋势线、完整 H2/H3 尝试入场计数、逆势突破失败的裁量规则也没有冒充已实现；已确认回调腿数不等于 H2/H3 计数。

## v10 的两项独立语义

v10 的 `structuredPullback` 增加两个必填字段，旧 v9 不接受这两个字段。旧草稿迁移为 `confirmation:before-breakout`、`keyRole:pullback-retest`，与旧执行一致，历史结果不迁移或补造新字段。

| 字段           | 保留的严格规则                                  | 独立实验规则                                                                             |
| -------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `confirmation` | `before-breakout`：形态必须在突破当根之前确认   | `signal-close`：突破当根完整收盘可确认两根以前的转折，再判断形态；确认时间可等于信号时间 |
| `keyRole`      | `pullback-retest`：已有关键位还须被本次回调触碰 | `impulse-context`：推进阶段取得关键位资格；本次回调不必重复触碰                          |

`signal-close` 不把信号 K 自身当成 pivot，不把确认信息回填到旧时间，也不改变下一分钟成交。左右各两根的确认窗口和突破整段推进极值的定义均保持。

`impulse-context` 的 pivot 身份仍在推进起点确定：起点在已知高低点的逆侧，最初推进或延伸阶段有效穿越，资格在回调开始时冻结。EMA 则必须在推进起点以前已有两次验证，并且起点收盘在当时 EMA 的顺侧或相等；此资格在起点冻结。两者任一满足即可。之后反向收盘超过原有 0.25A0 容差仍会使关键位失效；信号收盘必须在当前关键位顺侧。它表达“推进突破已知位置／位于已验证均线顺侧”，不冒充“推进起点恰好触碰支撑”。

第二轮保留五个固定版本：严格原规则、仅放宽确认时点、无形态的回踩关键位、无形态的推进背景关键位、无关键位与形态的简单基线。主假设事前固定为 `sp-context`；确认时点的对照不能成为主假设失败后的替代赢家。本轮不叠加两个新选项，也不修改 ATR、仓位、退出或成本。

## 账户之外的机会观察

原生研究入口对 v10 结构策略运行独立观察状态，复用同一指标与结构识别代码。它保留原 EMA 方向生命周期、首突破消费及失效规则，只不读取账户持仓、冷却与订单拒绝。实际交易仍受原风控约束；观察结果不生成订单。

`opportunityDiagnostics` 与交易 `results` 分开保存，每个候选保留完整终止计数及首次突破快照。回调资格、关键位、形态和烛形门槛同时记录，避免首个拒绝原因遮蔽后面的条件。不同候选的共同机会由标的、方向、setup 和信号时点对齐。它是当前识别器下的机会集合，不是所有可能市场形态的普查。

实际账户在持仓、冷却或退出期间会重置可识别推进的起点；独立观察器持续观察，可能给同次突破分配不同的推进原点。因此观察器不是账户交易 setup ID 的严格超集，不能直接用两者计数差解释被风控拦截的交易。政策间的机会比较使用同一观察器路径，账户结果仍单独评价。

`opportunity_diagnostics.py` 从冻结 [机会协议](../research/trend/structured-v2/opportunity-plan.json) 读取 6 小时／24 小时两个前向期限。下一分钟模拟入场，初始 R 与真实账户的 2 倍信号 ATR 和价格取整一致；分别检查 +1R／+2R 与 −1R 的首次到达顺序。分钟开盘先于区间高低点，同一分钟区间双触碰标为不确定，尾部不足完整期限单独排除。完整期限的 MFE／MAE 不在首次触碰时截断。手续费、滑点及历史资金费另行归因，标签和固定期限单位持仓净 R 均不是可执行账户收益，重叠机会也不能当作独立交易样本。

## 数据与实验分离

`scripts/trend/study.py` 是现有回放与评价的适配层，只负责目录、分组和门禁。

| 对象                 | 职责                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------- |
| `catalog.json`       | 可复用的数据来源、哈希、覆盖范围、资金费覆盖和曝光登记；不含策略参数                        |
| `experiment.json`    | 固定策略与少量对照、成本、验收条件；分别声明标的分组、时间窗口和需要执行的交叉单元          |
| `development-input/` | 编译为现有 runner 接受的计划和数据清单，绑定两者来源；不复制分钟行情                        |
| 阶段凭证             | 从原始结果重算资格和验收，绑定选择、配置、账本和输入 SHA；不接受手填的 `passed`             |
| 数据目录后继         | 仅允许给预留来源补充所声明的未来数据；保留父目录 SHA 和所有旧来源，实验无需随数据更新而改写 |

本轮分组如下，日期结束日均不含：

| 阶段     | 标的             | 日期                     | 证据身份                                                     |
| -------- | ---------------- | ------------------------ | ------------------------------------------------------------ |
| 开发     | BTC、ETH、BNB    | 2022-09-01 至 2024-01-01 | 已知历史，只用于开发与机制诊断                               |
| 验证     | SOL、XRP、DOGE   | 2024-09-01 至 2026-10-01 | 时间与币种均离开本轮开发域，但历史已研究过，仍标记为复用数据 |
| 最终留出 | AVAX、ATOM、NEAR | 2026-10-08 至 2027-10-08 | 预留未来时间及不同标的；完整数据尚不存在，不运行             |

分组是事前选定的存续合约，不是时点完整交易池或彼此独立的资产类别。最小阶段间隔七天，四天预热仅作上下文，不计入账户或评价日期。当前策略没有监督学习的未来收益标签，故 `purgeDays=0`；若后来加入标签或事件预测，必须另外声明标签跨度和清除重叠的方法，不能把七天间隔当成通用泄漏保证。

目录导入会把已使用历史登记为曝光；不能通过删掉一条曝光记录、改来源路径或把 `known-reused` 改个名字变成样本外。冻结时间和曝光仍是可核对的本地声明，不是第三方可信时间戳，也不能证明研究者从未在其他地方看过数据。

## 阶段门禁和有限对照

首轮主方案固定为 `sp-primary`，有五个对照；第二轮固定为 `sp-context`，有四个对照。每轮都没有参数网格，没有按结果替换主方案。

开发阶段要求每币至少 20 笔、至少两个币盈利、逐币平均净 R 的中位数为正，且合计基础成本净收益为正、日终回撤不超过 10%。开发只运行基础成本，不冒充已经通过成本压力。任一项失败即封存失败凭证，不解锁验证。

验证和最终留出只继承主方案与基线，各自完整回放基础与双倍手续费／滑点。正式验收要求至少 180 天、总交易至少 100 笔、每币至少 20 笔；主方案两种成本均净盈利且日终回撤不超过 10%；7 天和 28 天共同日期块 bootstrap 的平均日收益 95% 区间下界都大于零。配对优于基线只是诊断，不能替代绝对正期望。

每个阶段只有一个固定主假设。消融结论用于解释这一轮，若据此重设主方案，必须新建实验并承认已经消耗的数据。反复根据留出结果修改规则仍会过拟合留出；本流程没有实现论文中的特殊可复用留出算法，也不声称获得其统计保证。[Dwork 等人的原论文](https://arxiv.org/abs/1506.02629)

## 运行与复核

以下命令复核已封存的首轮配置 v9 和第二轮配置 v10，须使用对应的原二进制及新的输出路径。新实验的构建、运行与评价入口见[研究架构](TREND-RESEARCH-ARCHITECTURE.md#统一研究入口)，两轮结果见[研究总索引](../research/trend/README.md)。

```sh
bun run research:trend study preflight --catalog research/trend/structured/catalog.json --experiment research/trend/structured/experiment.json
bun run research:trend study compile --catalog research/trend/structured/catalog.json --experiment research/trend/structured/experiment.json --cell development --output tmp/structured-development-input
bun run research:trend run --plan tmp/structured-development-input/plan.json --manifest tmp/structured-development-input/manifest.json --binary tmp/quant-structured-target/release/trend --output tmp/structured-development-run --workers 3
bun run research:trend study seal --compilation tmp/structured-development-input/compilation.json --run tmp/structured-development-run --output tmp/structured-development-seal.json
```

第二轮复核使用对应的 v10 二进制与已冻结输入：

```sh
bun run research:trend run --plan research/trend/structured-v2/development-input/plan.json --manifest research/trend/structured-v2/development-input/manifest.json --binary tmp/quant-structured-v2-target/release/trend --output tmp/structured-v2-replay-check --workers 3
bun run research:trend diagnose opportunities --plan research/trend/structured-v2/development-input/plan.json --manifest research/trend/structured-v2/development-input/manifest.json --input tmp/structured-v2-replay-check --opportunity-plan research/trend/structured-v2/opportunity-plan.json --output tmp/structured-v2-opportunity-check.json
```

后续编译需要传入所有前置阶段凭证，验证阶段还要执行 `bun run research:trend evaluate transfer` 再封存；不能用通用报告中的盈利数字手工解锁。数据目录 `extend` 命令只接纳原冻结实验声明的未来数据，不改旧数据或标的。它不启动自动采集、计划任务或交易。

`setup_diagnostics.py` 汇总实际账户路径的推进、回调、首次突破、拒绝原因及准入计数，并核对已成交快照的因果时间；`trade_diagnostics.py` 单独评价完整交易与成本。形态通过之后仍可能被成交约束、仓位或风控拒绝，不能把不同账户的交易数差直接当作同一批机会的预测准确率。独立 `opportunity_diagnostics.py` 负责共同市场机会与完整前向期限；三者分工，不互相替代。
