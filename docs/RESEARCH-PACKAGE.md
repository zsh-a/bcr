# Reader 资料包 v2（独立分卷）

资料集合中的「Reader 完整资料包」将所选集合、已保存笔记、可选草稿，以及引用到的 Reader 源文件和章节快照一起下载。使用前先打开 Reader 并等待书库加载；源文件读取与恢复使用该书库的存储。

## 导出与恢复

1. 在全局搜索的「资料集合」中展开「Reader 完整资料包」，选择集合及是否包含草稿，选择单卷源文件上限（默认 128 MiB），点击「检查资料包」。
2. 预览遍历最初引用和全部关联修订，显示可用、来源或章节缺失、历史版本不一致、暂不支持的来源，以及去重后的源文件大小。检查会实际读取源文件并校验内容哈希。章节缺失但源文件仍可读时，仍会打包该文件。
3. 预览每卷的书籍、源文件大小、章节快照大小和预计总量；选择卷号，点击「生成并下载资料包」。每次只生成一卷，保存后再选择下一卷；可取消并重新生成。文件名包含资料包标识和卷号。集合内容使用检查时的快照；要包含后续编辑，请重新检查。检查或生成期间 Reader 书库变化会要求重试。
4. 在另一个浏览器打开 Reader，再选择资料包。系统先校验路径、版本、文件大小和内容哈希，再显示新增、复用、跳过与冲突副本数量。取消预览不会恢复资料。
5. 确认后先恢复 Reader 资料，再合并集合。通过集合的「回到原文」打开恢复副本，并核验和高亮引用。EPUB 等二进制出版物重新解析图片资源；引用身份与正文快照保留，刷新后仍可定位。跨 HTML 文本节点的引用也支持高亮。

检查、生成和导入校验过程中显示当前阶段与文件处理百分比，可点击「取消资料包操作」立即返回选择状态并重试。百分比针对当前文件或步骤，不代表整个资料包的总进度。关闭搜索面板也会取消正在进行的检查、生成或校验；取消后的结果不会再显示预览或触发下载。

取消信号会中断哈希流读取和 ZIP 文件处理，哈希计算定期让出主线程以响应操作。少数不能中断的清单读取会在返回后检查取消状态并丢弃结果。确认恢复后的持久化流程不提供取消，完成或失败后会显示结果；取消预览不会写入书籍或集合。

## 分卷任务与来源状态

检查完成后自动在本地 SQLite 保存当前导出任务：集合和目录快照、容量计划、卷号与输出状态。每个工作区保留最近一个任务；再次检查成功会替换它。刷新或重新打开面板后，点击「核验并继续上次任务」重新检查来源身份、正文快照及源文件哈希，成功后默认选中尚无输出记录的卷。继续任务使用原集合快照；后续笔记编辑需要重新检查才能进入新资料包。

刷新后将上次的「正在生成/正在保存」显示为未完成，可重新生成整卷；不提供文件字节级断点续写，也不保存文件句柄。已有下载记录不能证明文件仍在磁盘上。「清除任务记录」只删除任务元数据，保留已经导出的文件。任务写入失败时显示未保存提示，避免误以为刷新后可以继续。

恢复面板保留最近一套分卷目录，按源文件哈希重新核验已恢复、缺失、需核对或修复的来源，支持按卷筛选与手动刷新。损坏的源文件可用所属分卷重新恢复；如果本机副本已修改，仍遵循原有保护规则，不直接覆盖。

任务记录使用 v2 状态码（如 `saving`、`saved`、`downloaded`），展示文案独立维护。读取时兼容 v1 中文状态，后续保存升级为 v2；上次仍在运行的状态统一恢复为 `interrupted`。资料包 ZIP 格式仍为 v2，不受任务记录版本变化影响。

## 实现边界

`ResearchPackagePanel` 只组装表单与展示组件；`ResearchPackageViews` 展示续传、导出、恢复及来源汇总。`useResearchPackageController` 编排业务命令，`useResearchPackageAction` 集中管理取消和过期结果隔离，`useResearchPackageRecords` 管理本地记录加载与串行保存。文件选择、下载 URL 生命周期位于 `researchPackageFiles`，其中选择器仍在点击调用栈中打开。

引用展开、状态分类与绑定组合位于 `researchPackageReferences`，保持原始引用、历史顺序和绑定顺序；目录校验使用按书籍 ID 建立的索引，每本书只计算一次身份。任务状态、旧记录迁移与来源展示规则由独立的类型和纯函数维护。

## 文件契约

v2 外层 ZIP 只允许四个文件，不接受目录、重复路径或未知路径：

```text
manifest.json
catalog.json
research.json
reader.zip
```

`manifest.json` 使用 `format: "bcr-research-package"`、`version: 2`，`volume` 保存目录哈希 `set` 和从 1 开始的卷号 `index`；`entries` 为 `catalog.json`、`research.json` 与 `reader.zip` 分别记录 `path`、字节数 `size` 和 BLAKE3 `hash`。`research.json` 复用集合备份 v1，包含原始引用、笔记和全部关联记录。`reader.zip` 复用 Reader 备份 v1，内部 `reader.json` 保存书籍身份、章节快照与源文件清单，源文件位于 `sources/<hash>`，再次校验大小和哈希。

每卷携带相同的集合快照和完整 `catalog.json`，后者使用 `format: "bcr-research-volumes"`、`version: 1`，记录集合 JSON 的 `researchHash`、总卷数 `total`，以及每本书的原 ID、恢复目标 ID、标题、源文件哈希和所属卷号。导入会校验本卷书籍身份与目录一致；缺卷不影响本卷恢复。仍支持导入旧版三文件 v1 包。

集合 JSON 与分卷目录各上限 16 MiB，单卷 Reader 源文件最多 512 MiB、Reader 清单最多 64 MiB，外层有效载荷最多 600 MiB。容量预检按源文件哈希去重；共享同一源文件的不同书籍快照同卷保存，所有章节快照均计入预算。单本源文件或同源快照组超限会提前报错。预计总量包含完整集合、目录、章节快照与保守的 ZIP 开销预算。

浏览器每次只生成所选卷，不保留全部分卷 Blob。支持文件选择接口的环境提供「直接保存当前卷」：选择目标文件后，从存储逐个读取源文件流，边写入边校验大小与哈希；内层 Reader ZIP 直接进入外层 ZIP，不先创建完整 ZIP Blob。输出遵循背压，目标写入变慢时暂停读取。内存存储的降级实现也按需复制 64 KiB 分块，避免额外复制整个源文件。内层 ZIP 写入完成后再追加 `manifest.json`，v2 格式和旧导入器仍兼容，条目顺序不影响校验。

只有外层 ZIP 和目标文件均关闭成功才显示「已保存到文件」。取消、源文件损坏、快照变化或目标写入失败会中止整条流水线，取消源读取并请求中止目标流；失败不会显示保存成功。选择文件窗口由浏览器控制，取消选择后可以重试。

原有「生成并下载资料包」仍保留，下载后释放 URL；不支持文件选择接口的环境使用这一路径。该兼容路径仍在内存中组装单卷，可选择较小容量。章节与集合 JSON、已加载书库本身仍占用内存，流式输出不意味着应用总内存恒定。

## 身份与失败恢复

恢复书籍使用由包内书籍快照和源文件清单确定的 `research-…` 身份。即使本机有同名、同原始 ID 的书籍，也保留本机书籍并新增恢复副本；同一二进制文件的不同正文快照也分别保留。

集合摘录的可选 `readerBindings` 保存原书籍 ID 到恢复副本的独立映射；可选 `volume: {set, index, total}` 保留来源的分卷信息。每卷使用完整目录建立相同映射，所以乱序或重复导入不会因缺少其它卷而产生集合副本。未恢复来源的引用会提示所需卷号和资料包标识，补齐后自动重新核验。恢复面板同时列出本套资料的来源恢复状态。核验、回跳和再次打包时应用映射；原始 `route`、`citation`、正文及关联历史不改写。再次导出到另一浏览器时继续组合映射。普通 JSON 集合备份也保留该字段；Markdown 中仍记录原始来源和修订历史。

重复导入同一资料包复用书籍；集合遵循现有备份的确定性冲突副本规则。已恢复书籍的正文或章节结构若被修改，会拒绝覆盖并提示处理该副本。仅源文件缺失或损坏时，使用已校验的包内文件修复，保留本机书籍元数据。

Reader 自动保存与资料包恢复共用串行写入队列，启动及后台恢复读取也经过该队列，避免提前读取未提交的临时目录。源文件在队列外准备，提交时重新读取当前状态：期间新增的其它书籍会保留，删除的书籍不会被旧书库快照带回。同一资料包并发导入时复用相同身份；待复用书籍在准备或提交期间被删除、修改正文时，停止该次恢复并提示重新检查。

每次异步持久化后都会检查书库、阅读进度、排版、书签、批注、导航历史和搜索会话是否变化；有变化就使用最新状态重新写入。恢复成功只追加书籍，不重新初始化 Reader，因此当前阅读位置、搜索命中与高亮保持在最新状态。旧 Reader 运行实例的排队任务不能写入新会话。

确认恢复前，先将资料包身份、源文件清单、章节快照和带来源映射的集合快照写入本地恢复日志。日志持久化失败时不写入 Reader。日志记录待恢复、Reader 已保存、集合已合并和完成四个阶段；当前页面同一时刻只跟踪一项未完成的恢复任务。

重新打开 Reader 的资料包面板后，可点击「继续恢复」。续接会核验实际书籍和源文件，复用内容寻址存储中已写入的文件，并重新保存 Reader 书库与会话。即使源文件已写入、书库尚未提交，也可根据日志重建。缺少或损坏的文件需要重新选择同一资料包分卷；身份不匹配时在生成恢复预览和替换来源目录之前拒绝；确认恢复时再次检查身份。已修改的 Reader 正文仍遵循拒绝覆盖规则，可保留修改并结束任务跟踪。

集合合并与本次恢复的完成凭据写入同一个元数据值。即使集合已写入、日志尚未推进，续接也会识别该凭据，避免重复合并；中断后修改的笔记、重命名和删除的集合不会被本次任务重新导入。普通集合编辑保留内部凭据，导出的备份不包含该凭据。完成后的新一次确认导入仍按正常冲突规则处理。续接时首先通过集合串行队列读取持久化凭据；凭据存在时仅完成日志收尾，不再读取或重建 Reader 来源。因此用户在提交后修改正文、删除书籍或清理源文件，不会被当作本次导入的未完成工作。日志阶段本身不能代替该凭据；缺少凭据时仍执行实际恢复与核验。

Reader 存储与集合 SQLite 之间没有跨库事务，Reader 书库和会话也仍分键保存；这里提供可续接流程，不是跨库回滚。已经写入的源文件保留供重试使用，不自动删除共享文件。「结束跟踪」只清除日志，保留已恢复的书籍和集合。续接完成后清除旧恢复预览并重新核验来源汇总；已删除的来源会显示缺失。来源核验失败单独提示，不把已完成的恢复显示为失败。恢复日志加载绑定 Store 生命周期与请求版本，切换 Store、卸载和较旧请求的延迟返回不会覆盖新状态。恢复日志只保存元数据，不保存二进制源文件；导入仍在内存中读取单卷，尚未实现临时文件缓存或流式导入。浏览器必须保留原本地存储，清除站点数据后需重新选择资料包。

## 恢复日志 v2

恢复日志分为一份不可变快照与一条小型进度记录。快照保存任务身份、带映射的集合和 Reader 章节清单；进度只保存任务 ID、资料包身份、阶段和快照哈希，最大 4 KiB。阶段切换不会重写或重新解码完整快照，面板读取 v2 进度也不加载快照或 Reader 解码模块。

创建任务时先写快照，再发布进度指针，两者都成功后才写 Reader。继续恢复时核验快照哈希及任务身份。仍兼容 v1 完整日志；未完成的旧任务在续接时迁移，迁移期间旧日志在新进度指针写入前保持可读。

完成时先保存完成标记，再尝试清理快照。清理失败不撤销完成状态；重新打开面板后通过任务队列重新确认任务已完成，再重试清理。已完成的 v1 日志也会在面板加载后压缩为 v2 简要记录。清理前重新读取当前任务，避免旧清理请求删除新任务的快照。

每个 Store 的任务队列管理一个快照槽位。初次写快照后、进度发布前中断时可能留下无指针快照；下一次创建任务会覆盖该槽位，结束跟踪也会尝试清理。源文件存储与集合完成凭据不受日志压缩影响。缺失或损坏的待恢复快照会阻止导入；已有持久化完成凭据时仍可直接完成日志收尾。

## 当前边界与验证

本阶段只迁移 Reader 源文件。Document、Media 等来源的摘录和笔记仍保留，但源文件不随包迁移。历史引用会保留全部证据快照；若本机只有更新后的源文件，不能据此重建旧版原文件，回跳时仍需重新核验。资料包不应用导出端的全局排版设置、阅读进度、书签或批注。

运行 `node scripts/verify-research-package.mjs` 验证 Markdown 与 EPUB、原始和修订来源、笔记与草稿、真实下载、全新浏览器存储恢复、损坏包、取消、重复导入、跨节点高亮、插图及刷新恢复。该脚本已加入浏览器 CI。单元测试覆盖哈希损坏、独立映射及再次迁移、预览缺失与旧版本、同源不同快照、源文件损坏修复、Reader 写入失败及集合写入失败后的重试。

`node scripts/verify-research-package-cancel.mjs` 通过暂停真实 Blob 流读取，验证检查与生成中途取消、关闭面板、旧任务延迟结束、立即重试，以及手机尺寸下取消导入校验再恢复。该脚本同样纳入浏览器 CI。底层摘要测试覆盖字节进度、挂起读取取消、预先取消、部分读取后取消及流锁释放。

`persistenceQueue.test.ts` 对两种写入顺序（先自动保存、先恢复）注入暂停，验证新增/删除书籍、修改阅读进度与排版、保留搜索命中，以及刷新恢复的一致性；另外覆盖会话写入失败后的书库补偿、队列继续工作、并发重复导入和待复用资料被修改/删除。资料包浏览器走查也暂停真实 SQLite 写入，在等待期间修改书库并触发自动保存，验证恢复和刷新后的结果。

`node scripts/verify-research-volumes.mjs` 验证两个 EPUB 的逐卷真实下载、全新浏览器乱序与重复恢复、缺卷提示、补齐后引用回跳、高亮、插图及刷新。已加入浏览器 CI。单元测试还覆盖源文件去重、快照容量边界、单源超限和伪造卷号。

`node scripts/verify-research-stream.mjs` 使用文件选择接口测试替身和真实 OPFS 可写文件流，验证直接保存的两卷文件在全新浏览器中恢复、乱序和重复导入、引用高亮、图片及刷新。原生系统文件选择窗口不在自动化覆盖范围内。单元测试覆盖慢速目标、背压限制源读取、写入/关闭失败、中途取消、挂起源读取取消、重试，以及禁止导出路径调用整文件 Blob 读取。

`node scripts/verify-research-task.mjs` 验证导出一卷后刷新、恢复原任务、默认选择下一卷，以及两卷在新浏览器中的乱序恢复和引用回跳。任务测试覆盖中断状态、篡改快照、来源变化/损坏、修复后重试，以及任务记录的串行写入、失败恢复和清除。

`node scripts/verify-research-recovery.mjs` 在真实浏览器中分别暂停于源文件已暂存、Reader 书库已写入、Reader 恢复完成和集合合并完成，关闭页面后重新打开并续接，验证书籍与集合不重复，以及中断后修改的笔记得到保留。单元测试另覆盖初始日志写入失败、写入成功后抛错、日志推进失败、身份不匹配、源文件缺失、并发续接和损坏日志。

阶段 1 回归还覆盖完成凭据存在时删除书籍、修改正文和源文件缺失，缺少凭据时不信任日志阶段，以及选择错误资料包后保留来源目录。浏览器脚本验证续接后的来源汇总，并挂载真实 React hook 验证请求乱序、切换 Store 与卸载后的结果隔离。

日志 v2 测试覆盖大章节下进度写入大小、快照只写一次、初始快照写入失败、v1 迁移各写入边界、快照丢失/损坏/身份不匹配、完成后清理失败重试，以及延迟清理不能删除新任务快照。
