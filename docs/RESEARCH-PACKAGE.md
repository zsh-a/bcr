# Reader 资料包 v1

资料集合中的「Reader 完整资料包」将所选集合、已保存笔记、可选草稿，以及引用到的 Reader 源文件和章节快照一起下载。使用前先打开 Reader 并等待书库加载；源文件读取与恢复使用该书库的存储。

## 导出与恢复

1. 在全局搜索的「资料集合」中展开「Reader 完整资料包」，选择集合及是否包含草稿，点击「检查资料包」。
2. 预览遍历最初引用和全部关联修订，显示可用、来源或章节缺失、历史版本不一致、暂不支持的来源，以及去重后的源文件大小。检查会实际读取源文件并校验内容哈希。章节缺失但源文件仍可读时，仍会打包该文件。
3. 点击「生成并下载资料包」。集合内容使用检查时的快照；要包含后续编辑，请重新检查。检查或生成期间 Reader 书库变化会要求重试。
4. 在另一个浏览器打开 Reader，再选择资料包。系统先校验路径、版本、文件大小和内容哈希，再显示新增、复用、跳过与冲突副本数量。取消预览不会恢复资料。
5. 确认后先恢复 Reader 资料，再合并集合。通过集合的「回到原文」打开恢复副本，并核验和高亮引用。EPUB 等二进制出版物重新解析图片资源；引用身份与正文快照保留，刷新后仍可定位。跨 HTML 文本节点的引用也支持高亮。

检查、生成和导入校验过程中显示当前阶段与文件处理百分比，可点击「取消资料包操作」立即返回选择状态并重试。百分比针对当前文件或步骤，不代表整个资料包的总进度。关闭搜索面板也会取消正在进行的检查、生成或校验；取消后的结果不会再显示预览或触发下载。

取消信号会中断哈希流读取和 ZIP 文件处理，哈希计算定期让出主线程以响应操作。少数不能中断的清单读取会在返回后检查取消状态并丢弃结果。确认恢复后的持久化流程不提供取消，完成或失败后会显示结果；取消预览不会写入书籍或集合。

## 文件契约

外层 ZIP 只允许三个文件，不接受目录、重复路径或未知路径：

```text
manifest.json
research.json
reader.zip
```

`manifest.json` 使用 `format: "bcr-research-package"`、`version: 1`，`entries` 为 `research.json` 与 `reader.zip` 分别记录 `path`、字节数 `size` 和 BLAKE3 `hash`。`research.json` 复用集合备份 v1，包含原始引用、笔记和全部关联记录。`reader.zip` 复用 Reader 备份 v1，内部 `reader.json` 保存书籍身份、章节快照与源文件清单，源文件位于 `sources/<hash>`，再次校验大小和哈希。

集合 JSON 上限 16 MiB，Reader 源文件总量上限 512 MiB、Reader 清单上限 64 MiB，外层有效载荷上限 600 MiB。预览的大小只计算源文件，不含章节快照和 ZIP 开销。本版在浏览器内组装 ZIP；大文件仍受设备可用内存限制。

## 身份与失败恢复

恢复书籍使用由包内书籍快照和源文件清单确定的 `research-…` 身份。即使本机有同名、同原始 ID 的书籍，也保留本机书籍并新增恢复副本；同一二进制文件的不同正文快照也分别保留。

集合摘录的可选 `readerBindings` 保存原书籍 ID 到恢复副本的独立映射。核验、回跳和再次打包时应用映射；原始 `route`、`citation`、正文及关联历史不改写。再次导出到另一浏览器时继续组合映射。普通 JSON 集合备份也保留该字段；Markdown 中仍记录原始来源和修订历史。

重复导入同一资料包复用书籍；集合遵循现有备份的确定性冲突副本规则。已恢复书籍的正文或章节结构若被修改，会拒绝覆盖并提示处理该副本。仅源文件缺失或损坏时，使用已校验的包内文件修复，保留本机书籍元数据。

Reader 自动保存与资料包恢复共用串行写入队列，启动及后台恢复读取也经过该队列，避免提前读取未提交的临时目录。源文件在队列外准备，提交时重新读取当前状态：期间新增的其它书籍会保留，删除的书籍不会被旧书库快照带回。同一资料包并发导入时复用相同身份；待复用书籍在准备或提交期间被删除、修改正文时，停止该次恢复并提示重新检查。

每次异步持久化后都会检查书库、阅读进度、排版、书签、批注、导航历史和搜索会话是否变化；有变化就使用最新状态重新写入。恢复成功只追加书籍，不重新初始化 Reader，因此当前阅读位置、搜索命中与高亮保持在最新状态。旧 Reader 运行实例的排队任务不能写入新会话。

Reader 存储与集合 SQLite 之间没有跨库事务，Reader 书库和会话也仍分键保存。Reader 持久化失败时不发布新书籍，并尝试将已经写入的临时书库恢复为当前内存状态；重新保存也失败时明确显示错误，供后续重试。浏览器在写入途中被强制终止的完整事务恢复不在本轮保证范围内。集合写入失败时原集合保持不变，已恢复的 Reader 资料保留，并明确提示重试。重试复用这些书籍，不重复添加。失败过程中已经写入的内容寻址源文件可能保留供重试使用，不自动删除共享文件。

## 当前边界与验证

本阶段只迁移 Reader 源文件。Document、Media 等来源的摘录和笔记仍保留，但源文件不随包迁移。历史引用会保留全部证据快照；若本机只有更新后的源文件，不能据此重建旧版原文件，回跳时仍需重新核验。资料包不应用导出端的全局排版设置、阅读进度、书签或批注。

运行 `node scripts/verify-research-package.mjs` 验证 Markdown 与 EPUB、原始和修订来源、笔记与草稿、真实下载、全新浏览器存储恢复、损坏包、取消、重复导入、跨节点高亮、插图及刷新恢复。该脚本已加入浏览器 CI。单元测试覆盖哈希损坏、独立映射及再次迁移、预览缺失与旧版本、同源不同快照、源文件损坏修复、Reader 写入失败及集合写入失败后的重试。

`node scripts/verify-research-package-cancel.mjs` 通过暂停真实 Blob 流读取，验证检查与生成中途取消、关闭面板、旧任务延迟结束、立即重试，以及手机尺寸下取消导入校验再恢复。该脚本同样纳入浏览器 CI。底层摘要测试覆盖字节进度、挂起读取取消、预先取消、部分读取后取消及流锁释放。

`persistenceQueue.test.ts` 对两种写入顺序（先自动保存、先恢复）注入暂停，验证新增/删除书籍、修改阅读进度与排版、保留搜索命中，以及刷新恢复的一致性；另外覆盖会话写入失败后的书库补偿、队列继续工作、并发重复导入和待复用资料被修改/删除。资料包浏览器走查也暂停真实 SQLite 写入，在等待期间修改书库并触发自动保存，验证恢复和刷新后的结果。
