# 工作区交互约定

[文档](README.md) → 交互

工作区以内容为中心。所有应用使用 `@bcr/react` 的控件和令牌，领域组件管理内容与任务状态；字体、颜色与响应式尺度见[主题规范](THEMING.md)。

## 共享组件

| 组件                | 约定                                                              |
| ------------------- | ----------------------------------------------------------------- |
| `AppToolbar`        | 统一高度与工作区入口，承载当前对象和主要操作                      |
| `ActionMenu`        | 命令使用 `variant="menu"`；包含输入和选择器的设置使用默认 `panel` |
| `ContextMenu`       | 按触发位置定位，限制在视口内，提供键盘与触屏等价入口              |
| `Dialog` / `Drawer` | 原生模态、背景隔离、Tab 循环、Escape 与关闭后焦点恢复             |
| `Toast`             | 成功与信息提示自动消失，警告与错误保留；悬停或聚焦暂停计时        |
| `EmptyState`        | 简短说明和明确的下一步，区分空内容与加载状态                      |
| `ResourceHeader`    | 资源范围或标题，以及一个主要创建入口                              |
| `ResourceSearch`    | 独占整行，清除后保留范围与输入焦点                                |
| `ResourceViews`     | 范围切换，支持方向键与 Home/End，Tab 只进入当前项                 |

命令菜单采用紧凑行、固定图标槽与左对齐文字；分隔线区分操作组，删除使用危险语义色。方向键、Home/End 选择，Escape 关闭并恢复焦点。不要把纯命令放进设置面板，以免出现大块留白或图标换行。

弹窗位置由共享样式负责。普通弹窗居中，Drawer 靠右，手机底部面板使用 `placement="sheet"`。响应式挂载采用 `useMediaQuery`，不能用仅视觉隐藏的普通容器模拟模态。

## 内容与操作

主要操作保留明确名称，低频操作进入菜单；手机先保证正文、表格或画布可用，再安排管理入口。示例与真实数据要有明确标识，状态使用“正在处理”“已保存到本机”等用户语言。

标题可以省略，菜单和时间不能被长标题挤到下一行。行布局应在组件基础样式中定义，响应式规则只调整尺寸与呈现。文字、按钮、徽标各有收缩边界，避免在多个入口重复补布局。

输入法确认不能触发意外提交或跳转。导航先完成必要的草稿保存，异步写入失败保留输入并提供重试；技术诊断留在详情。

## 触控与键盘

桌面命令行使用 `--h-menu-row`，触屏使用至少 44px 的 `--h-hit-target`。不要因图标变小而缩小点击区域。关闭按钮、工作区入口和移动端主操作遵循同一规则。

导航弹层不自动聚焦文本输入，以免刚打开就召唤键盘；用户主动进入搜索后再输入。关闭弹层返回触发对象，保持正文位置。动效尊重减少动态效果偏好。

阅读工具显隐不改变正文几何。滑动、长按、拖选与点按需要区分，不能让翻页或点击处理抢走选字手势。

## 领域布局

- **知识库**：先集合，再搜索，再全部／收藏／最近；普通浏览使用目录树，搜索与最近列表保留自己的排序。正文与属性面板分开，手机使用模态列表和信息抽屉。
- **Reader**：书库使用统一资源搜索与管理菜单；正文纸张配色独立于界面主题。目录、书签、PDF 页面浏览与进度操作分层呈现。
- **绘图**：顶部负责图表与文件操作，原生画布负责绘制与内容设置。手机的低频操作进入更多菜单，名称和保存状态保持可见。

更多行为见[知识库](KNOWLEDGE-WORKBENCH.md)、[Reader](READER-ARCHITECTURE.md)和[绘图](DRAWING.md)。

## 样式边界

共享辅助文字、控件和正文使用各自的文字令牌。数字与代码可以使用等宽字体；标题、标签与说明采用正文字体。

圆角、间距、色彩和动效复用共享令牌。领域可以保留行情涨跌、图表系列和阅读内容的语义配色，界面控件不再维护另一套主题。

应用重置样式必须限制在领域根节点，并避让共享控件；领域页面不修改 `body` 布局。避免依赖样式加载顺序决定菜单显示和行布局。

## 验证

先按[开发指南](DEVELOPMENT.md#验证)启动服务器，再运行对应命令：

| 检查                                                      | 覆盖                                     |
| --------------------------------------------------------- | ---------------------------------------- |
| `test:browser:layout`                                     | 应用入口、遮挡、溢出与多种视口           |
| `test:browser:ui`                                         | 弹窗位置、焦点、导入导出、状态提示与主题 |
| `test:browser:resources`                                  | 资源范围、搜索、排序、属性与抽屉         |
| `test:browser:reader:menu`、`test:browser:reader:toolbar` | 菜单、长按、触控目标与单一入口           |
| `test:browser:diagram`                                    | 图表命令、图标同行、键盘导航与手机布局   |

对应源码位于 [共享控件](../packages/react/src/ui.tsx)、[应用控件](../packages/react/src/AppControls.tsx)和[控件样式](../packages/react/src/ui.css)。
