# 知识库图片与附件

## 使用

- 编辑器支持粘贴、拖入文件、顶部「插入附件」和 `/图片`、`/附件`。异步导入期间继续编辑时，插入位置跟随文档变化；被替换的选区已经修改则取消插入。切换笔记、导出、同步和页面更新会先等待正在进行的导入。
- 本地图片在编辑和阅读视图内展示，点击查看原图。文件链接展示名称和大小，点击打开预览。PDF、音频、视频可直接查看，其他文件可下载。支持的文档还能交给 Reader 阅读。
- PDF 复用 Reader 的 PDF 渲染器，预览一次只渲染一页并限制画布尺寸；分页、取消和关闭会释放对应资源，手机端也不依赖浏览器原生 PDF 插件。
- 图片或附件右键支持查看、下载、替换、移除当前引用；触屏长按、键盘 Shift+F10 同样打开菜单。「信息 → 附件」列出当前笔记引用的文件。
- 外部图片先显示加载入口，明确点击后才请求外部地址。允许跨域读取的图片可以「保存到本机」；不会自动将所有远端图片转换成本地附件。
- 文本、PDF、EPUB、DOCX 等按页或段落提取，超长页可继续读取。图片文字识别由现有 Document 本地任务运行，首次使用需要下载模型，当前支持英语和日语。尚未加入中文识别模型，也不自动识别扫描 PDF。

## 持久化与身份

Markdown 保存 `![名称](attachment:<id>)` 或 `[名称](attachment:<id>)`；ID 不依赖笔记所在目录。`KnowledgeContent.attachments` 登记不可变的 ID、BLAKE3 摘要、名称、MIME、字节数、创建时间及可选图片尺寸。本地沿用分记录元数据存储，二进制存放在共享 BinaryStore 的 `artifacts/knowledge/attachments/<hash>`，同样内容只存一份。

文件先流式写入并核对摘要、长度，再提交元数据记录，最后插入正文。元数据失败不会向正文发布一个未保存的附件身份。导入重试可用经过校验的同内容原文件修复损坏文件；恢复和同步也按同样顺序处理，未完成时不提交笔记内容。

Worker 计算内容摘要、读取图片尺寸并为大图生成 WebP 缩略图；GIF 保留原始动画预览。缩略图、分页文本为可重建的派生数据，本地键包含来源摘要和提取版本，未进入内容同步。预览 Blob URL 随组件释放。

通用计算缓存清理保护整个 `knowledge/attachments` 命名空间。移除正文引用不会物理删除文件，以保护草稿、撤销记录、历史版本和待确认同步。当前没有自动孤儿附件回收或附件回收站；未引用的文件及登记仍保留，并进入完整备份和同步。

## 备份、同步与导出

- **完整 ZIP 备份**：含 `knowledge/attachments.json` 和 `knowledge/attachments/<hash>.bin`，同时保留笔记、引用来源、集合和文件夹。清单版本为 4；旧的纯文本备份仍可读取。恢复时流式解压并校验二进制内容，通过后再预览和提交元数据。
- **GitHub**：二进制以 Git Blob 上传，文件和笔记一起生成一次提交；私有仓库下载沿用凭证，请求二进制流并在本地校验。已存在的摘要文件避免重复上传，仓库其他内容保持原样。所有设备应使用支持附件清单的客户端。
- **Markdown 附件包**：笔记按逻辑路径导出，稳定附件 URI 改为相对 `_attachments` 路径，文件按摘要去重，目录冲突时另选名称。保留标题、标签、时间、集合和引用来源的 YAML 字段。含附件的单篇导出同样生成 ZIP。包中的笔记间 BCR 稳定链接暂不转换为可读路径；这不是完整的 Obsidian Vault 交换格式，恢复知识库请用完整备份。

单个本地附件上限 128 MiB；ZIP 解压总量和一次同步附件总量上限 512 MiB。GitHub 上传为限制 Base64 编码内存，单个附件上限 16 MiB，较大文件用 ZIP 迁移。原有文本单文件 2 MiB、文本传输总量 16 MiB 限制继续生效。

备份预览取消或同步中断可能留下已校验但未被正文引用的文件；它们不会使笔记部分提交。网站数据删除仍会删除本地原文件，应定期导出备份。

## AI 与验证

`knowledge_list_attachments` 分页返回元数据、版本摘要、当前引用笔记及读取能力。`knowledge_read_attachment` 必须指定 ID 与版本摘要，每次最多返回 12000 字符，包含来源身份、页码、提取引擎及后续读取位置。图片 OCR 需显式请求，二进制和 Base64 不进入工具响应。模型任务可取消，文本提取缓存可复用。

```sh
bun run test apps/studio/tests/knowledge-attachments.test.ts
BASE_URL=http://localhost:5199 bun run test:browser:knowledge:attachments
```

单元测试覆盖身份验证、失败写入与重试、引用历史、完整 ZIP 和相对路径导出、两设备二进制 Git 同步、Unicode 分页、OCR 任务接入与 AI 来源约束。浏览器回归使用临时设备和 GitHub 仓库替身，覆盖图片上传与 Worker 预览、粘贴/拖放、右键/撤销、PDF 文本提取、跨设备恢复及窄屏。OCR 模型执行另由 Document 测试负责，本回归不下载模型权重。
