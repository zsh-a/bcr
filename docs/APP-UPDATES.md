# 全局应用更新

Studio 和独立 Reader 的入口均挂载 `AppUpdateProvider`，全站共享一份更新提示。Service Worker 仍采用后台检测、用户确认激活的方式：首次启动、返回可见页面、网络恢复及每 30 分钟检查；首次离线安装不会提示升级。

提示可以收起，保留“新版本可用”入口；路由切换不丢失提示。另一标签页激活新版本不会强制刷新当前页面，当前页面仍需确认并保存。

## 领域接入

领域通过 `@bcr/react` 的 `useUpdateParticipant({ blocked, save })` 注册保护，无需订阅 Service Worker 事件。隐藏但仍挂载的领域同样参与，卸载时自动注销。

- `blocked()` 返回阻止更新的原因，空闲时返回 `null`。用户点击时检查，保存完成后再次检查。
- `save()` 必须等待持久化完成，失败必须抛出错误；不能仅安排一个延迟写入。
- 任一保存失败会显示错误、恢复交互，保留旧版本并允许重试。
- 保存期间工作区暂时不可交互，防止确认后继续输入；不会自动取消运行任务。

当前接入 Reader 阅读位置与书库、笔记草稿和待确认重命名、知识库同步、资料集合、Agent 会话和宿主上报的运行任务。新增领域有独立的编辑草稿、导入或异步保存时，仍需注册自己的保护，不能仅依赖运行任务计数。

`packages/react/tests/updateCoordinator.test.ts` 验证保存顺序、重复请求、忙碌保护、失败重试和卸载。`bun run test:pwa` 使用生产产物验证全局提示、移动布局、真实升级、跨标签页行为及数据保存；Agent 浏览器回归额外验证待审批任务阻止更新。
