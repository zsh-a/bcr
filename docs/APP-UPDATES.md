# 应用更新与恢复

[文档](README.md) → 更新

各入口通过 `AppUpdateProvider` 共享更新提示与保存流程。Service Worker 在生产模式下注册，首次打开、返回可见页面、网络恢复及定时检查时查找新版本。

## 更新与恢复

出现「新版本可用」后，确认更新会先检查忙碌状态、保存当前内容，再激活新版本并刷新。保存失败时显示错误，保留当前页面，允许重试。

提示可以收起，路由切换不会丢失更新入口。另一标签页更新不会强制刷新当前页面；当前页面仍需完成自己的保存流程。

手机仍显示旧版时：

1. 保持联网，切回应用或重新打开原入口，让后台检查运行。
2. 等待新版本下载完成，通过应用内提示更新；后台任务或保存错误需要先处理。
3. 若启动失败页持续报告模块加载错误，可使用页面上的「清除缓存并重载」。

启动恢复按钮清除同源 Service Worker 和 Cache Storage，随后重新加载；它不删除 OPFS、IndexedDB 或 localStorage 中的内容。缓存模型和离线资源可能需要重新下载，因此应联网使用。

浏览器设置中的“清除站点数据”会删除本地内容，与上述恢复按钮不同。需要清理整个站点前，先导出书库、知识库与图表。

「本地持久化不可用」也不等同于版本未更新。应检查安全上下文、存储权限、剩余容量与启动错误，见[部署排查](DEPLOYMENT.md#常见问题)。

## 领域接入

通过 `@bcr/react` 注册：

```ts
useUpdateParticipant({
  blocked: () => (busy ? "正在处理，请稍后更新。" : null),
  save: () => store.flush(),
});
```

- `blocked()` 返回阻止原因，空闲时为 `null`；更新前与保存后都会检查。
- `save()` 必须等待持久化完成，失败需抛出错误，不能只安排延迟写入。
- 保存期间工作区暂时不可交互，避免保存后继续修改；协调器不自动取消任务。
- 隐藏但仍挂载的领域也参与保存，卸载时自动注销。

Reader、知识库、资料集合、绘图、Agent 会话及宿主运行任务已有接入。新增领域应注册自己的编辑草稿、导入与保存状态，不能只依赖任务计数。
