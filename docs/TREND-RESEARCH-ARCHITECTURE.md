# 趋势研究架构与维护边界

本轮审查范围是 Quant Lab 的永续趋势模块、共享 Rust 引擎与离线研究工具。现有 Runtime / Worker / Artifact 分层可以继续使用；优先调整会影响研究正确性和历史证据的边界，不另建策略插件框架或第二套撮合引擎。

## 已完成的调整

| 问题                                           | 调整                                                                | 后续研究得到的保证                                    |
| ---------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------- |
| 复用较长缓存时，ATR / EMA 起点随此前运行变化   | 数据覆盖与实际回放窗口分开；浏览器和 CLI 按当前配置固定起点         | 同一配置不因运行顺序或其他候选的预热需求改变结果      |
| 历史恢复失败后，自动保存可能用空状态覆盖原记录 | 会话存储集中恢复、写入门禁和串行队列；恢复成功才允许运行和写入      | 失败不覆盖原历史，单次保存失败不会阻塞之后的队列      |
| 历史类型通过当前类型推导，旧校验借用当前校验   | `recorded.ts` 显式冻结历史结构和范围；`archive.ts` 做展示和草稿迁移 | 新增当前字段不会改变旧版契约；旧结果不被静默升级      |

| 默认研究命令指向旧计划和旧运行目录             | 新命令要求显式计划与输出；冻结路径禁止写入                          | 新研究不能通过默认参数覆盖旧证据                      |
| 专用报告硬编码执行器、日期、币数和结论         | 旧生成器归档为文本；新报告读取计划、收据与原始账本                  | 报告身份来自实际结果，不把新回放误标为旧研究          |
| 回放、统计和报告使用同一源码指纹               | 回放协议、评价身份、报告生成分开                                    | 改排版不重跑分钟数据；新评价保留原开发期选择          |
| 跳空成交位置难以对应原入场依据                 | 信号时冻结 `entrySignal`，经持仓传入交易及信号事件                  | 解释使用当时收盘、边界与 ATR，不以成交价倒推信号      |
| 图上止损跨交易相连、缺少突破窗口参照           | 按持仓分段投影止损；通道仅取当根开盘前 N 根完整交易 K 线            | 空仓与不同交易断开，显示聚合不改变策略周期            |
| 图表变化与回测缓存版本耦合                     | 图表任务独立绑定 `trend-chart-2`                                    | 更新展示不要求重算交易账本                            |
| 逐币与组合指标含义混用、缺少评价约定           | Rust 输出版本化逐币评价；Python 只重新评价合计账户日权益            | 不平均单币 Sharpe，不把日终回撤标成分钟回撤           |
| 前端常量代替实际二进制身份                     | WASM 提供执行版本，Worker 回放前核验，并将核验值写入结果            | 旧 WASM 无法被标为新执行器并发布到新缓存              |
| 持仓采样、保护计算和退出状态混在一起           | 持仓记录状态，管理模块返回保护提案；Engine 消费绑定持仓的退出意图   | 已完成分钟与交易 K 线明确区分，条件止损与市价退出分开 |
| Engine 与 Evaluator 分别维护交易统计           | Evaluator 统一汇总；Engine 保留现金记账，旧 Metrics 投影同一统计    | 增加统计不再要求修改两个胜负或盈亏计数器              |
| 历史外层校验不足、选择与结果异步错配           | 独立历史记录解码；结果加载状态绑定运行及产物身份                    | 损坏记录不能打开写门，新配置不能配上旧结果            |
| 候选名称影响费用、研究日权益存在两个读取口径   | 显式成本情景；统一规范日序列并核对兼容副本                          | 敏感性命名不改实验成本，组合与逐币日权益保持一致      |

回测执行器为 `trend-continuation-11`，配置仍为 v5，评价契约为 `metrics.evaluation.version: 2`。v11 收敛职责并要求运行中的 WASM 自报身份；新缓存与此前未经身份核验的结果隔离。Worker 核验失败会释放引擎，禁止回放和结果发布。v10 的数量步长与保本成交取整修复继续保留，技术验证及研究规则差异见[关键技术验证](BINANCE-TREND.md#关键技术验证)。v8 引入的冻结信号快照继续保留，旧结果缺少快照或新评价时仍可读取。规则编号、配置结构版本、回测执行器、评价与图表执行器版本是不同概念。已发布 v5/v6 执行器研究仍按原字节保存。

新回测默认使用 4 小时、只做多、20 根突破、2 ATR 止损、10 根反向通道退出及日线背景过滤；无过滤方案保留为对照基线。两种预设都保留现有资金、成交成本、独立成本门槛和风控。背景过滤只能约束新开仓，不能彻底排除局部震荡，可能错过启动，也不保证收益提升。会话通过 `draftDefaultsVersion: 1` 记录一次迁移：仅未标记且 `breakout + none` 的旧草稿改为背景过滤，其余参数和历史运行不变；用户随后明确选择 `none` 会在恢复时保留。

## 职责划分

| 层                 | 主要位置                                                          | 应承担的职责                                                               |
| ------------------ | ----------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 当前配置与历史契约 | `packages/quant-core/src/trend/`                                  | 当前配置验证、周期及预热；冻结旧结构；历史记录外层解码及展示适配           |
| 行情和来源         | `packages/market-data/src/binance/`、`execution/data.ts`          | 官方校验、分钟完整性、必要的日档案恢复、不可变引用                         |
| 会话               | `apps/quant-lab/src/trend/session/`                               | store 负责恢复及串行持久化；研究 Hook 编排任务；结果加载器独立管理读取状态 |
| 浏览器执行适配     | `execution/window.ts`、`compute.ts`                               | 冻结输入、确定实际窗口、分片、取消、结果发布                               |
| 图表与入场解释     | `execution/chart.ts`、`trend/chart.ts`、`channels.ts`、`entry.ts` | 分段止损、因果通道、冻结快照优先与历史参考来源区分                         |
| 分片输入适配       | `crates/quant/src/trend/replay.rs`                                | 原始 CSV 校验与顺序、窗口截取、向引擎分批推进                              |
| 事件编排与账户     | Rust `trend/engine.rs`                                            | 分钟执行顺序、成交与现金记账；提交保护提案，统一消费退出意图               |
| 行情与信号         | Rust `trend/indicators.rs`、`signals.rs`、`background.rs`         | 聚合完整 K 线、计算指标，产生带时间依据的入场候选                          |
| 持仓状态           | Rust `trend/position.rs`                                          | 冻结信号 ATR、初始距离，记录入场后的有利／不利运行                         |
| 持仓管理           | Rust `trend/management.rs`                                        | 根据明确时点的行情和持仓状态，返回止损提案或通道退出意图                   |
| 风险状态           | Rust `trend/risk.rs`                                              | 日内开仓门禁、冷却及风险退出决策；不执行平仓或改现金                       |
| 逐币评价契约       | Rust `trend/evaluation.rs`、TypeScript `trend/evaluation.ts`      | 完整账本与估值累计、日/月明细、风险指标、成本归因和版本                    |
| 原生入口           | `crates/quant/src/bin/trend.rs`                                   | 校验冻结档案，逐候选确定预热，批量运行同一个领域引擎                       |
| 研究协议           | `scripts/trend/protocol.py`、`warmup.py`                          | 计划校验、资金分配、显式策略／成本情景展开、预热需求                       |
| 证据与运行         | `artifacts.py`、`download.py`、`research.py`                      | 哈希、原子写入、只读保护、收据审计、原生进程与缓存                         |
| 规范日权益与评价   | `daily.py`、`evaluation.py`                                       | 校验兼容副本，统一读取日权益；组合统计、开发期选择                         |
| 报告与展示         | `report.py`、`plot.py`                                            | 消费已审计数据和明确成本情景，输出表格与曲线                               |

`MinuteClose` 与 `TradingClose` 分别表达已完成的分钟行情和带同根 ATR 的已完成交易 K 线。`Position.signal_atr`、`initial_distance` 保持冻结；保护函数只返回 `StopUpdate`，不会直接改持仓。`ExitIntent` 记录持仓 ID、触发时点、可执行时点与原因，Engine 负责优先级与一次性消费；条件止损仍按是否触价决定成交。风控的冷却连亏计数与评价的最长连亏含义不同，分别保留。

当前 ATR 方案仍按分钟收盘、冻结 ATR 和最大有利运行决策。动态 ATR、收盘 R 保本或越线后不可撤销的市价退出需要独立的规则变更；本轮职责拆分不启用这些新实验。

浏览器结果的 `window` 是实际回放区间，`manifest` 是数据覆盖区间。旧结果没有 `window` 时保留其清单起点口径，不能根据新配置公式倒推、重写旧结果。资金费、成交价和标记价格仍来自冻结输入；缺失数据明确失败。

`entrySignal` 保存信号收盘时间、价格、突破边界、ATR，以及通道信号的回看根数；候选到持仓、账本的传递不重新计算它。旧交易无快照时，展示层只在精确交易周期、入场对齐且冻结行情和通道齐全时推导参考，并标注为历史行情推导；不根据粗粒度图表推断原信号，也不补造 ATR。图表读取和独立缓存只生成展示产物，不改写原交易与研究证据。

Rust、TypeScript 和 Python 暂时保留各自的小型预热函数，通过 `crates/quant/fixtures/trend-contract.json` 共用默认配置、周期映射和 19 个验证向量约束漂移。修改周期或预热规则时必须同步契约与三端实现；修改执行语义还须更新执行器身份。

评价 v2 的逐币计算由同一 Rust 引擎提供给原生研究和浏览器，展示层只消费完整结果，不从缩略图或分页交易重新推导。`crates/quant/fixtures/trend-evaluation-contract.json` 固定约定与日权益向量，约束 Rust 与 Python 的账户日收益公式。新评价统一声明 UTC、365 日年化、无风险利率与 MAR 为 0、样本方差；CAGR、波动率及风险比率至少需 30 个完整日，零分母或非有限值为 `null`。30 日只是展示门槛。分钟回撤和日终回撤分别记录，最长回撤包含尚未恢复的区段；成本已进入成交和权益，只归因及对账，不重复扣除。公式与一手方法来源见[评价口径](BINANCE-TREND.md#评价口径)。

研究层 `trend-account-evaluation-2` 保留原始逐币 `metrics.evaluation`，先合计独立子账户的完整日终权益，再计算账户指标，明确标记 `drawdownSampling: daily-close`；账户 Calmar 的分母也是日终回撤。Python 继续负责相关性、月收益、盈利集中度、块重采样与冻结开发期选择。旧无版本评价走原分支，保持原统计；混合版本或不同约定拒绝汇总。新的评价身份写到新报告目录，不能覆盖旧证据或重新选择历史赢家。股票现有 252 个交易日、按盈利日计算的 PF 与趋势交易 PF 仍是不同口径，不因字段同名就混为一种统计。

浏览器会话历史仅保存轻量指标摘要和结果引用；完整评价、日/月序列随结果产物保存，选中运行时读取。`recorded-run.ts` 验证配置、行情清单、产物引用、运行信息和必需指标，历史可选字段继续允许缺失；损坏记录恢复失败时不开放保存。结果加载器用运行 ID 与产物引用绑定 `loading / ready / error` 状态，切换选择后立即屏蔽不匹配的旧结果，过期请求不得发布，读取失败可以单独重试。指标展示定义集中在 `results/evaluation.ts`，`TrendEvaluationPanel` 渲染指标和月表，`TrendPerformanceChart` 展示完整日序列；交易行情图只负责 K 线、通道和买卖点。

研究回放协议为 `trend-native-replay-3`。候选包含 `id`、策略和 `cost_scenario`，名称仅标识候选；参数敏感性与成本压力分别展开。执行、审计和报告消费同一协议定义；只有历史协议适配器按旧收据重现早期名称后缀的成本语义。评价 v2 的规范日序列来自 Rust `metrics.evaluation.daily`，`daily.py` 核对完整 UTC 日、连续时间与兼容 `row.daily` 的权益一致后提供给组合评价；未标版本的旧结果保留原读取口径。新源码指纹包含该适配器，不改写历史收据或重新选择旧研究赢家。

## 过时内容的处理

已从活跃入口移除四个历史专用报告/绘图脚本，源码保留在 `scripts/trend/legacy/`，不再用于生成新研究。更正 crate 中“仅支持日频 JSG、分钟模拟不在范围”的旧说明，去掉趋势文档将当前工作台统一描述为某个外部策略复刻的说法。

保留旧配置读取器、失败候选、原始研究计划、报告、曲线与图。它们是比较和审计的依据，策略表现差并不代表证据过时。`scripts/trend/frozen.json` 登记已发布文件的哈希及旧运行目录；审计核对已记录的身份链，不要求当前源码与历史源码相同。哈希一致只证明文件与记录一致，不能代替交易逻辑正确性验证，也不能补造未保留的历史二进制。

## 后续研究的最小流程

1. 另建研究计划，先固定候选、基线、窗口角色、总资金与子账户口径、成本压力和选择标准。现有报告使用过的区间只能作为已查看诊断。
2. 使用独立输出目录获取并冻结档案。派生 CSV 和资金费按内容存储，最后原子发布清单。
3. 用共享 Rust 引擎回放，先开发期选择，再按冻结选择展开其他窗口；不随检验结果重新选择历史赢家。
4. 核对原始账本、日历、配置、窗口与收据后生成评价；报告展示可独立更新，新的评价产物写到新的目录。
5. 扩展策略时先实现一个可单独检验的假设，继续共用撮合、成本与风险层，并验证下一分钟成交、已完成 K 线、分片一致性和账户对账。

具体命令见 [Binance 趋势研究](BINANCE-TREND.md#审计历史与运行新研究)。本次没有重跑或替换既有研究结论。

## 后续按需重构

- Rust 的入场、过滤、管理和方向仍使用通过验证的字符串。增加新分支时可迁为 serde 枚举，保留现有 JSON 拼写；当前无需引入动态插件机制。
- CLI 的批候选收集、浏览器结果的分页和导出仍可进一步拆分。现有规模下不阻塞研究，待增加组合执行或新输出类型时再抽取。
- EMA 在信号状态机内过滤，背景在候选入场时过滤；两者对回踩 setup 的影响不同。不能仅为代码统一把它们移到同一位置，而不承认策略行为发生变化。
- 目前多品种研究采用独立子账户汇总。共享资金池、组合波动目标及组合敞口需要独立的账户与分配模型，应作为新的研究协议和执行语义实现。
