# 内容项目与生成式页面

[文档](README.md) → 内容项目

“内容项目”（`/content`）把资料、模型、页面、知识库文稿、发布版本和经营记录组织在一起。人工界面与 AI 助手使用相同的数据校验、版本检查与持久化服务，数据保存在当前浏览器本机。

项目可以没有计算模型，也可以包含多个独立模型、多个页面。提供空白专题、固定成本、做饭损耗、住房与通勤四种预设；示例参数均为自设假设。旧版健身卡项目及发布快照保持可读、可复算。

## 开始创作

1. 在工具栏选择预设并新建选题，也可以打开“AI 创作”，请助手建立项目。
2. 在“资料”保存来源 URL、正文、文件、采集日期、适用地区、作者和许可。通过“提供文件给助手”上传文件后，助手可以读取文本、导入价格 CSV、登记证据或恢复归档。
3. 在“页面”调整参数试算，编辑文字、主题与横竖版。试算不会立即写入；点击“保存页面与参数”才更新项目。新增模型、公式、情景和页面结构可交给助手处理，也可在高级模型定义中编辑。
4. 文稿继续使用知识库编辑器。通过助手现有知识库工具创建笔记，再将 noteId 关联到项目。纯页面作品可以不关联文稿。
5. 保存发布快照，导出图文发布包与可恢复归档。后续修改不会改变已经保存的快照。
6. 发布后记录平台、链接、制作工时、费用、收入及指标观察窗口。缺失数据保留为空，平台指标定义单独保存。

例如对助手说：

> 根据我提供的价格表，建立做饭与外卖比较。现金与时间分别展示，损耗率可以调整，做成竖版页面，最后导出发布包。

助手会读取契约、资料和当前版本，通过领域工具建立或更新模型与页面。每次写入先展示修改预览；一组相关模型、页面与证据变更可以一次确认。网页文本按来源数据提供给助手；生成页面不执行任意 JavaScript。

页面与模型表单显式保存，文稿沿用知识库自动保存。未保存的当前项目表单会阻止助手覆盖；过期 revision 被拒绝，失败时保留输入。不同窗口写入以持久化版本和 Web Locks 协调，不提供实时协同编辑。

## 助手能力

插件注册共享能力 `content.workspace`，即使未打开内容项目页面也可以调用。

| 工具                                 | 职责                                                                 |
| ------------------------------------ | -------------------------------------------------------------------- |
| `content_catalog`                    | 返回模型、页面、区块修改及项目变更契约和预设示例                     |
| `content_list` / `content_read`      | 查找项目，读取版本、资料、页面、模型运行身份与知识库文稿版本         |
| `content_create`                     | 创建空白或预设项目                                                   |
| `content_apply`                      | 一次提交相关变更；按稳定 ID 更新模型、证据、页面、发布记录或局部区块 |
| `content_evaluate`                   | 确定性试算，不持久化临时参数                                         |
| `content_file` / `content_import`    | 分页读取提供的文本文件，导入证据或价格 CSV                           |
| `content_release`                    | 固定项目、文稿、页面、模型结果与依赖版本                             |
| `content_export` / `content_restore` | 导出可下载的发布包或归档，核验并恢复独立副本                         |

写入操作进入现有 AgentHost 审批。创建、批量修改、来源导入与快照使用 requestId；保存回执与项目在同一个 IndexedDB 事务中提交，重试可以复用原回执，同一 requestId 不能对应不同输入。恢复使用归档内容身份生成确定的副本 ID。导出返回持久文件引用，聊天结果卡片可以下载，不把 ZIP/base64 放入对话。

助手修改页面时先读取人工内容与 revision，使用 `pagePatches` 更新指定区块。移除区块时应同步更新父区块的 children；模型删除和受影响页面的修改可以放入同一个变更集。页面数据有唯一持久化来源，没有另建聊天专用页面状态。

## 通用模型

`@bcr/economics-core/analysis` 定义 `AnalysisModel@1`，由纯计算函数执行。模型包含参数、公式、情景和可选的参数扫描：

- 数值以十进制字符串存储，decimal.js 使用独立配置和 40 位有效数字。显示保留两位小数；绘图阶段转换为 JS number，图表显示值不作为计算依据。
- 每个参数记录单位、实际记录/外部资料/自设假设分类和可选证据 ID。
- 表达式是受校验的结构：参数或公式引用、有单位的常量，以及 add、subtract、multiply、divide、min、max、ceil、floor。没有 eval 或代码执行。
- 单位支持 `CNY`、`min`、`meal` 等命名基本单位的乘除组合，例如 `CNY/meal`；`1` 表示无量纲。加减比较要求维度相同，乘除推导维度，并核对公式声明。分钟与小时等转换需要显式公式，不做隐含折价或单位换算。
- 缺失输入、零除、未知引用、循环依赖和单位错误会阻止提交。不会以零代替失败结果。
- 情景覆盖指定参数。敏感性扫描保存起止值与样本数，采样结果不是解析的临界点；需要精确临界点时定义对应公式。
- 模型最多 64 个参数、64 个公式、24 个情景、120 个扫描点；表达式限制深度和节点数。每个项目最多 16 个模型。

运行身份包含模型定义、所用证据内容哈希和引擎版本。改动价格、公式或已关联证据后，绑定到旧运行的判断需要复核，原文保留。

通用价格 CSV 使用 UTF-8，保持原始十进制字符串。单模型时可以省略 model 列：

```csv
model,parameter,value
cost,ingredients,10.50
cost,loss,0.25
```

旧版 `fixed-use@1` 仍使用 `parameter,value` 和 fixed、variable、alternative、weeks 四个参数，保留原有连续持平、整数首次不贵、首次严格更便宜的算法和零次使用语义。

## 页面契约与渲染

`PageSpec@1` / `bcr-page-1` 保存 root、按稳定 ID 索引的 elements、主题与布局。页面目录包含 Stack、Columns、Heading、Text、Metric、Parameter、Chart、Table、Sources 九个组件。

模型绑定显式使用 model ID、参数 ID、输出 ID 和可选情景 ID。图表绑定相同单位的列；现金和时间需要分别展示。页面只存绑定关系，计算结果由模型产生。Text 可通过 model + reviewedRun 绑定判断；发布前必须复核所有过期的绑定判断。

[json-render](https://json-render.dev/docs) 负责组件注册和 React 页面渲染，BCR 在适配层校验完整页面图、组件属性、引用、循环、重复父节点和未连接区块。最多 20 页，每页 100 个区块、12 层嵌套。UI 组件属性使用 Zod 目录契约，项目和计算契约继续使用 Effect Schema。

首版页面通过工具调用整批校验并保存；聊天文本仍流式输出，页面尚未逐区块流式生成。人工可以修改文字、主题、版式、模型参数；结构调整由助手的局部变更工具完成。没有引入第二套拖拽编辑器或任意 React/TSX 执行环境。

React 预览、SVG 排版和静态 HTML 共用页面契约与真实数据。SVG 导出使用明确的版式计算，不依赖 DOM 截图；HTML 是无脚本静态作品，交互试算在 BCR 中进行。超长页面须拆分后导出图片。

## 发布包与归档

发布快照固定完整项目、可选文稿、通用模型的输入和结果、旧版模型结果、证据、页面目录版本、附件与字体。后续编辑不修改已有快照。未保存文稿、未复核判断或缺失依赖会阻止生成快照。

发布包包含：

- `title.txt`、`article.md`、`sources.md`、`release.json` 和字体许可。
- 通用页面的 `pages/<id>.json`、`.html`、`.svg`、`.png`，以及 `analysis.json` 的精确模型结果。
- 旧版项目的 `model.json`、图表、封面和文稿附件。正文里的图表与附件地址改写为相对路径。

项目归档继续使用 `bcr-content-package@1`。`manifest.json` 保存当前项目、页面、文稿、经营记录及历史快照，`assets/<hash>` 保存去重后的素材与导出字体。恢复前核验依赖闭包、路径、大小、内容哈希和快照摘要，再写入本机。恢复副本身份由归档决定，历史发布身份保持不变，重复恢复不会覆盖已修改的文稿。

每个证据素材最多 16 MiB；归档依赖最多 256 MiB / 500 个素材，清单最多 16 MiB；助手提供/导出的独立文件最多 300 MiB。独立文件位于 `content/exports/`，项目归档只收集实际项目依赖。

外部图片应先导入附件。网页获取目前支持粘贴原文或上传文件，不包含绕过浏览器跨域限制的抓取服务。Reader 原书等跨应用资料仍由各自应用迁移，本归档不打包整个书库。

## 实现边界

| 模块                                       | 职责                                           |
| ------------------------------------------ | ---------------------------------------------- |
| `@bcr/economics-core`                      | 旧版计算与通用模型契约、单位推导、确定性求值   |
| `@bcr/visual-renderer`                     | ECharts SVG SSR、通用结果图表、resvg WASM PNG  |
| `content/model.ts`                         | 项目契约、证据、运行身份与判断绑定             |
| `content/commands.ts`                      | 批量变更、稳定 ID、版本检查与幂等身份          |
| `content/agent.ts`                         | 领域工具适配与只读修改预览                     |
| `content/pages/`                           | 页面契约、json-render 目录、交互预览及静态导出 |
| `store.ts` / `assets.ts`                   | IndexedDB 事务、回执、Web Locks、不可变文件    |
| `service.ts` / `release.ts` / `archive.ts` | 知识库交接、发布屏障、版本快照与归档           |

服务归工作区所有，React 组件订阅状态，不拥有持久化队列。计算包不依赖 UI、存储和 DOM。没有增加新的 Agent 框架、服务端数据库或平行任务编排系统。

本轮不包含通用剪辑时间轴、配音、视频编码、自动平台发布与指标抓取。扩展这些能力时应接入领域命令和既有 Scheduler；旧计算引擎、页面目录和渲染器版本需要保留对应解码与渲染能力。

## 验证

```sh
bun run check
bun run test
bun run test:ci
BASE_URL=http://localhost:5199 bun run test:browser:content
BASE_URL=http://localhost:5199 bun run test:browser:content:agent
```

单元测试覆盖公式与单位、三种计算预设、空白专题、页面引用和执行属性校验、幂等回执、过期写入、未保存草稿、取消、磁盘失败和归档篡改。

助手浏览器验收使用模拟模型接口，执行真实 AgentHost 工具调用和审批，验证手工编辑保留、试算保存、发布下载、移动端布局、新浏览器恢复及 SVG/PNG/HTML 一致性。它不验证某个真实模型的生成质量，也不需要调用付费模型。截图与实际发布包写入 `scripts/shots/`，不提交仓库。
