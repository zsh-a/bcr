# 个人知识库与 Git 同步

入口：Studio 导航中的「个人知识库」，或直接访问 `/knowledge`。

写作、标签页、快速切换、双向链接、日记和模板的使用方式及兼容边界见 [知识工作台](./KNOWLEDGE-WORKBENCH.md)。

本机分记录存储、迁移备份与全局搜索增量更新见[存储文档](./KNOWLEDGE-STORAGE.md)；本地清单版本与 Git/ZIP 传输格式相互独立。

这是独立于 Reader 的本地优先 Markdown 知识库：可以直接手写笔记，也可以把已有资料集合的摘录、笔记和来源快照导入。无需部署 SiYuan / Trilium 服务，不同步它们的内部数据库。

## 开始使用

1. 运行 `bun run studio`，打开 `/knowledge`。
2. 新建笔记，填写标题、Markdown 正文、逗号分隔的标签，可按集合分类。输入时备份草稿，停顿 500ms 后保存到当前工作区元数据；界面显示保存状态。
3. 使用全局搜索的「个人笔记」分类检索正文；导入普通 Markdown，或从「资料集合」导入已有摘录。重复导入同一摘录不会覆盖已经整理过的笔记。
4. 「导出这篇笔记」生成带元数据的 Markdown；「导出知识库」生成包括集合、Markdown 和引用 JSON 的 ZIP。「恢复 ZIP 备份」先校验并预览，再选择保留本机、保留双方或替换同 ID 内容；不会删除备份之外的本机笔记，也不会恢复密钥或同步连接。

恢复采用一次知识库状态更新，写入失败时不先发布成功状态。预览后继续编辑或同步会使预览失效，须重新选择备份。存在同步冲突、待确认同步回执或正在同步时禁止恢复。替换的笔记旧版本进入现有历史（全库最多 100 个），集合没有独立修订历史，因此大批量替换前仍建议导出当前知识库。

备份读取限制压缩文件及解压文件合计 16 MiB、单文件 2 MiB；拒绝重复路径、路径穿越、未知文件、符号链接、加密条目和缺失的集合/引用关系。此备份不包括原书附件、本机历史或同步基线，不等同于整个浏览器工作区备份。

未连接仓库也可以编辑、搜索和导出。数据属于当前浏览器配置文件与网站 origin；清理网站数据或使用隐私窗口可能丢失本机数据。建议定期导出或同步。

## 两台设备使用同一仓库

1. 在 GitHub 创建一个**私有仓库**，勾选添加 README，使默认分支存在。
2. 创建 fine-grained personal access token，只授权该仓库的 **Contents: Read and write**。不需要工作流或组织管理权限。组织仓库可能还需要组织批准；受保护分支可能不允许直接推送。
3. 第一台设备打开「同步设置」，填写仓库地址（`https://github.com/you/notes` 或 `you/notes`）与 Token，点击「连接并同步」。自动识别默认分支；需要指定已有分支时展开「高级」。验证仓库和远端内容通过后才保存连接，首次同步会三方合并本机与远端笔记，冲突保留双方内容待选；如有冲突，「处理冲突」对话框提供「采用本机 / 采用远端 / 合并」三种处置。
4. 第二台设备填写同一连接，点击「连接并同步」，即可拉取笔记。顶栏状态点显示「已保存到本机 / 已保存 · N 条待同步 / 已同步 · 相对时间」，点开可见上次同步、待同步、立即同步、自动同步与同步设置；清除 Token 和断开连接位于「同步设置」对话框的「管理」区。
5. 可选开启「自动同步」：偏好按仓库与分支保存在当前浏览器，刷新后仍保留，但仅在 Token 可用时运行。笔记保存后约 3 秒、恢复联网、窗口聚焦时同步；知识库处于活动页面时每 30 秒检查一次。「同步设置」打开时暂停自动调度，关闭页面或切到其他应用后不做后台同步。

Token 默认仅存页面内存；可主动勾选「记住此设备」（localStorage），点击「连接并同步」后生效。设备记忆为浏览器明文存储，并非加密保险箱，同源脚本可以读取；只在可信个人设备上选择。Token 按仓库绑定，更换仓库会清空输入，新连接验证和保存成功后删除旧目标副本；清除 Token 保留仓库配置，断开连接同时清理当前凭据。本机笔记不会因断开而删除；有未处理冲突或尚未核对的远端提交时，不允许更换或断开仓库。已打开的其他标签页可能仍保留其内存凭据。凭据和自动同步偏好不写入工作区元数据、业务导出文件或仓库。所有 GitHub 请求直接从浏览器发往 `api.github.com`，不接受自定义服务器地址，不经过额外代理。没有 Token 时本机笔记仍可使用。

默认分支通过 [GitHub 仓库 API](https://docs.github.com/en/rest/repos/repos#get-a-repository) 的 `default_branch` 获取。连接验证只读取数据，不自动创建仓库或分支；写入权限和分支保护最终仍以同步提交结果为准。若连接已保存但同步失败，可直接重试「立即同步」。

私有仓库**不是端到端加密**：GitHub、仓库协作者及持有 Token 的人可能访问笔记。不要存入不适合上传 GitHub 的敏感资料。删除当前文件也不会擦除 Git 历史中的旧内容。

## 存储格式

```text
knowledge/
  manifest.json               # 格式声明：bcr-knowledge / version 1
  notes/<stable-id>.md         # YAML 元数据 + 原始 Markdown 正文
  citations/<stable-id>.json   # 引用快照、来源身份与本地回跳位置
  collections/<stable-id>.json
```

标题重命名和逻辑路径移动不改变文件身份。可以在外部编辑器修改 Markdown 正文，但需保留 YAML 中的 `bcr`、`id`、标题、时间、标签、集合以及存在的 `path` 字段，且物理文件名必须与 ID 一致。导入一般 Markdown 不要求这些元数据；应用会分配新身份。可读路径的格式升级、备份及旧客户端兼容限制见[路径与文件夹](./KNOWLEDGE-PATHS.md)。

仓库中其他文件不受影响。不上传 SQLite 数据库、检索索引、模型、缓存、Token、本机修订记录，也不上传 Reader 原书、PDF、音视频或图片附件。引用文字在另一台设备可读；「回到原文」需要该设备已有对应源资料。

此格式为后续 AI 检索、引用溯源与可审核修改提供基础；当前已接入单篇笔记的 AI 改写／续写（见下节），向量数据库、MCP 与自动改写代理仍未接入。

## 通用 AI 助手（可选）

统一入口为顶栏「AI」、Ctrl/⌘+J 或启动台「AI 助手」。助手是 Shell 中唯一的常驻浮窗，打开时保留当前工作区；/assistant 直达链接也打开同一宿主。旧的笔记专用内联面板和浮窗实现已移除。

- 支持拖动、边角缩放、展开/还原、收起、关闭和位置重置；位置与大小保存在本机，屏幕变小时自动约束到可见区域。拖动和缩放控件也支持方向键。
- 无需打开笔记即可对话；标题固定为 AI 助手，当前工作区单独显示。「当前内容」可以控制是否向模型附加当前选区与编辑工具。
- 领域通过 registerAgentCapability 注册工具和可选上下文。scope: workspace 的能力只在指定 domain 可用，scope: shared 的能力跨域可用；「领域能力」可逐项开关。
- 知识库检索与读取由宿主激活 knowledgePlugin 注册，未打开编辑器时也能使用；跨域搜索查询各工作区已发布的索引快照。当前笔记的选区与写入能力仅在知识库活动时提供。
- 只读工具自动执行，其他工具展示参数并等待确认。
- 编辑审批锁定提出时的原文、范围和目标；确认前切换目标、工作区或关闭能力会阻止写入。
- 编辑工具等待本机保存完成后才返回成功及笔记 ID/正文版本；存储失败或同步冲突会向模型返回工具错误，草稿保留。
- 当前笔记、选区和插件资料不再进入系统指令，改为带来源和版本的有界参考数据。此隔离降低提示注入风险，但不替代程序侧权限与审批。
- 知识库列表和 Agent 检索共用 Unicode 归一化及标题/标签/正文排序。结果包括实际命中片段、原文位置、笔记跳转地址和有界来源引用；当前仍是关键词检索，不是向量检索。全局搜索继续使用已有分块索引。
- 保存笔记与当前草稿读取均按 12000 字符分页；后续页必须携带首次返回的 version，版本变化时拒绝继续拼接。读取返回值标明当前草稿状态，选区读取有截断标记。
- 对话由宿主持有并在本机持久化。接口地址与模型可恢复；密钥默认仅在页面内存，也可显式选择标签页或设备保存，不进入知识库同步与导出。
- Agent WASM 运行时在首次请求模型时加载，支持流式响应、停止和最多 8 轮工具循环。
- 执行状态区分运行、等待审批、正常结束、达到轮次上限、取消和失败。达到上限会明确告知任务可能未完成；后续发送新指令是新一轮任务，不是断点恢复。

共享实现位于 packages/agent（运行时与能力注册）、packages/react（React 绑定）和 packages/agent-ui（通用对话 UI）。运行时源自 crates/agent-runtime 子模块。

## 同步与恢复规则

- GitHub Git Database API 按目录差异生成 tree / commit，仅以 `force: false` 更新分支；这是 Git 版本同步，不是本地 Git clone，也不是多人实时协作。
- 使用本机保存的共同版本进行三方合并。不同行的正文改动可自动合并；同一行、竞争插入、元数据同时修改、删除与修改竞争时保留冲突，不静默覆盖。
- 冲突记录持久化到本机，刷新仍在。打开「处理冲突」对话框，用词级差异对比本机、远端或合并结果，选择「采用本机」「采用远端」或「合并」；解决后再同步。合并保留本机的标题与路径，正文改动双方保留；采用某侧会把另一侧版本存入历史。
- 网络请求期间继续编辑不会被同步结果覆盖；新修改可能留待下一次同步。
- 远端提交前先保存待确认回执。如果推送成功但响应丢失，或最终本地写入失败，下次同步核对提交祖先关系再恢复。
- 每次最多重试 3 次非快进更新。公共仓库、损坏数据、不完整 tree、受管文件中的符号链接、远端历史重写均停止同步，保留本地内容。
- 本机最多保留 100 个修改前版本，包含删除记录。「版本历史」对话框分「本机版本」与「GitHub」两页，逐条列出（含相对时间与词级差异），每条可单独「恢复」为当前笔记；GitHub 页可读取当前笔记的远端提交并逐条恢复（恢复会生成本机修改，下次同步时提交）。恢复后生成新提交，不回退或强推远端历史。

当前容量边界：最多 5,000 篇笔记、1,000 个集合，单篇正文 500,000 字符；单个同步文件 2 MiB，同步文件合计 16 MiB。本机状态连同历史、基线、冲突及回执限制 32 MiB。达到限制会报错而不是截断数据。大量长笔记与频繁修订应考虑后续分记录存储升级。

离线编辑不依赖 GitHub。生产版沿用现有 Service Worker：首次联网加载知识库，待 Service Worker 接管后再在线打开/刷新一次，缓存所需动态资源，之后支持离线重新打开。首次访问未缓存资源时仍需网络；开发服务器不提供离线冷启动。

## 验证

```bash
bun run test apps/studio/tests/knowledge.test.ts
# 先启动 Studio 开发服务器；模拟 GitHub，不使用真实 Token 或外网仓库
BASE_URL=http://127.0.0.1:5199 node scripts/verify-knowledge.mjs
# 生产资源与关闭页面后的离线冷启动
bunx vp -C apps/studio build
BCR_KNOWLEDGE_PRODUCTION=1 node scripts/verify-knowledge.mjs
# 通用 AI 对话：用桩端点，不需要真实密钥或外网
bun run build:wasm:agent
BASE_URL=http://127.0.0.1:5199 node scripts/verify-general-agent-chat.mjs
```

单测覆盖格式验证、三方合并、持久化故障、双设备同步、提交响应丢失、推送竞态、历史恢复等；`knowledge-edit.test.ts` 另外覆盖区间编辑、基准失效丢弃与「改前留版本」。知识库浏览器走查使用两个隔离存储上下文，共享模拟 GitHub 对象数据库，覆盖全局搜索、双设备合并与冲突、刷新恢复、Markdown 安全预览、导入导出和移动端布局。通用助手走查另行检查全局打开、拖动缩放、收起还原、跨域会话与工具共享、能力开关、审批目标切换和移动端边界。
